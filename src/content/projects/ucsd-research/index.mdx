## Overview

Supercomputers like SDSC's **Expanse** give researchers thousands of CPU cores and racks of GPUs, but more hardware doesn't automatically mean faster results. Ask for too few cores and a job crawls; ask for too many and the extra hardware sits idle while it burns the allocation. And every model behaves differently on every chip.

Over two summers our team built **benchmarking tools that answer those questions with data**. You give them an ML workload and they run it systematically across different hardware configurations, record performance, and show where the real speed-up is. It's software for getting the most out of hardware. Our benchmarking-workflow poster was featured on the ICICLE research organization's website, and the workflow is now used across the center.

## 2024: PRISM

**PRISM** (*Performance Rater Intended for Supercomputer training Models*) is a multi-framework benchmarking system for training convolutional neural networks (CNNs) on supercomputers.

<Figure src="ucsd-research/prism-visual.png" variant="dark" alt="Visualization of a CNN model generated by PRISM during benchmarking: columns of colored squares, one per layer, on a dark background" caption="A CNN model visualized by PRISM during a benchmark run" />

### How it works

- **Two frameworks, one interface.** PRISM runs matching CNN models in **PyTorch** and **TensorFlow**, so researchers can compare frameworks as well as hardware.
- **Configurable from the command line.** Precision, epochs, batch size and image size are set through `argparse`, and models can be saved in **ONNX** format for training and inference.
- **Automated scaling sweeps.** A central Python script uses `subprocess` to launch shell scripts that submit **SLURM job arrays**, running each model on 1 to 64 allocated CPU cores and on GPU. Job arrays account for run-to-run variation.
- **A standardized dataset.** We built **SDSC-10**, a custom dataset modeled after ImageNet-10 with over 300,000 images, standardized to 192 × 128 and cropped with a rolling-window, edge-density algorithm.

### Results

Adding cores sped training up quickly at first, but the gains **flattened past 32 cores** while efficiency kept falling, for both frameworks. TensorFlow scaled more efficiently, durations were similar for both, and the **GPU beat every CPU configuration** by a wide margin.

### Impact

The PRISM workflow is being used to evaluate model performance for **real-time monitoring of soybean fields in Iowa**, where models judge crop health from drone imagery. It helped accelerate and optimize the ICICLE group's agriculture models and set up a standard, rigorous way to run the same kind of optimization for future models on UCSD's supercomputer.

## 2025: MLPerf Inference

The second summer moved from **training** to **inference**. We built an automated, reproducible workflow to run the industry-standard **MLPerf Inference** benchmark suite on Expanse, measuring how well its GPUs handle demanding ML workloads.

### How it works

- **Reproducible environments** with Conda, and **Bash scripts** that automate every step
- **MLCFlow** to manage and evaluate the MLPerf Inference benchmarks
- **SLURM** jobs on two GPU systems: **NVIDIA A100-PCIE-40GB** and **Tesla V100-SXM2-32GB**
- Each run records **accuracy and throughput**. A run only counts if the model's accuracy meets the MLPerf threshold, and throughput is the measure of hardware performance

We benchmarked **BERT** (language understanding), **3D-UNet** (kidney tumor segmentation in medical images), **Stable Diffusion** (text to image), and set up **Mixtral** (general LLM) and **Whisper** (speech to text), which were still in progress at poster time.

The A100s beat the V100s on every benchmark, by a margin consistent with NVIDIA's published data, and by more than **2×** on the image-heavy 3D-UNet and Stable Diffusion models. Our absolute throughput was lower than other published results, which points to a less optimized inference implementation and is a lead for future tuning.

### Impact

The workflow gives the center a reusable way to **assess hardware under ML workloads, guide new hardware purchases, and spot hardware defects**. Next steps are CPU inference results for comparison and publishing results to **MLCommons** as a reference for other researchers with Expanse-like hardware.
